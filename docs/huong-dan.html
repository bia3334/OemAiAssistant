OEM AI Assistant

PoC ứng dụng Windows (WPF, .NET 8) tích hợp AI chạy trên thiết bị. Tài liệu này giải thích cấu trúc thư mục, lý do chia 3 project, cách chạy app và cách AI được nạp vào.

1. Tổng quan

App có 2 khung:

  • Bên trái — Thiết bị OEM: hãng, model, Windows, CPU %, RAM, pin. Đây là số liệu thật của máy, cập nhật mỗi 2 giây.
  • Bên phải — Trợ lý AI: ô chat. Mỗi câu hỏi được gửi tới một model AI (Phi-4-mini) chạy ngay trên máy qua Microsoft Foundry Local — không cần Internet, không cần API key. AI được cung cấp telemetry làm ngữ cảnh, và nhớ 8 tin nhắn gần nhất của cuộc trò chuyện.

3. Vì sao chia ra 3 project

Mỗi project trả lời một câu hỏi khác nhau, và có một quy tắc bắt buộc: phụ thuộc chỉ được trỏ vào trong, về phía Core.

Desktop (UI)

Hiển thị ra sao? XAML, ViewModel, nút bấm, loading. Biết cả Core và Infrastructure (để lắp ráp).

Infrastructure

Làm bằng cách nào? Win32, registry, HTTP tới Foundry Local. Chỉ biết Core.

Core

Làm cái gì? Model dữ liệu, interface, luồng nghiệp vụ. Không biết ai cả — không WPF, không HTTP, không Windows.

4. Một câu hỏi chạy qua code như thế nào

  1. UI Người dùng gõ câu hỏi, nhấn Gửi (hoặc Enter). Nút được bind tới AskCommand.
  2. UI MainViewModel.AskAsync thêm bong bóng chat của người dùng. AskCommand.IsRunning = true → thanh loading và nút Huỷ tự hiện, nút Gửi tự xám (chống bấm 2 lần).
  3. UI ViewModel gọi DeviceAssistant.AskAsync(câu hỏi, lịch sử, cancellationToken).
  4. Core DeviceAssistant lấy telemetry mới nhất qua IDeviceTelemetryService.
  5. Infra WindowsDeviceTelemetryService đọc CPU (GetSystemTimes), RAM (GlobalMemoryStatusEx), pin (GetSystemPowerStatus), hãng/model (registry BIOS).
  6. Core Ghép prompt: system message = vai trò + telemetry làm ngữ cảnh; sau đó là 8 tin nhắn gần nhất; cuối cùng là câu hỏi hiện tại. Gửi qua IAIService.
  7. Infra FoundryLocalAIService POST tới http://127.0.0.1:<port>/v1/chat/completions (chuẩn OpenAI). Model chạy trên GPU và trả lời.
  8. UI ViewModel thêm bong bóng AI, lưu cặp hỏi/đáp vào lịch sử, cập nhật panel telemetry bằng đúng bản chụp AI đã dùng. IsRunning = false → loading tắt.

Bấm Huỷ giữa chừng → CancellationToken được huỷ, request HTTP dừng ngay, chat hiện "Đã huỷ yêu cầu".

6. AI có tự load model không?

Có, một phần. Ở lần hỏi đầu tiên, FoundryLocalAIService tự chuẩn bị theo các bước sau, rồi nhớ kết quả cho những lần sau:

  1. Chạy foundry server status -o json để biết server Foundry Local có đang chạy không và ở cổng nào (cổng thay đổi mỗi lần khởi động, nên không thể viết cứng).
  2. Nếu server chưa chạy → tự chạy foundry server start.
  3. Chạy foundry model list --loaded -o json để xem model nào đang trong bộ nhớ → dùng model đó.
  4. Nếu chưa có model nào → tự chạy foundry model load phi-4-mini.
  5. Gửi câu hỏi. Nếu request lỗi (vd server khởi động lại sang cổng khác), lần sau sẽ dò lại từ đầu.
ViệcApp tự làm?
Khởi động server Foundry Local✅ Có
Tìm cổng của server✅ Có
Load model vào bộ nhớ✅ Có, nếu chưa có model nào được load
Tải model về máy (vài GB)❌ Không — tải trước bằng foundry model download …
Chọn đúng biến thể GPU thay vì NPU❌ Không — xem cảnh báo bên dưới
Vì sao nên tự load bản GPU trước khi chạy app? Khi app tự load theo tên chung phi-4-mini, Foundry Local tự chọn biến thể nó cho là tốt nhất — trên máy này là bản NPU. Nhưng NPU Intel của máy đang lỗi driver (ZE_RESULT_ERROR_DEVICE_LOST), nên câu hỏi sẽ báo lỗi. Chạy foundry model load Phi-4-mini-instruct-cuda-gpu:5 trước thì app sẽ thấy bản GPU đang được load và dùng luôn bản đó.
Lần hỏi đầu tiên chậm (~90 giây) vì GPU phải khởi tạo CUDA. Các lần sau chỉ 0.3–3 giây. Trước khi demo, nên hỏi thử 1 câu để "làm nóng".

Model chạy ở đâu?

Phi-4-mini chạy trên GPU NVIDIA RTX 5060 của máy, qua CUDA. Không có dữ liệu nào rời khỏi máy. Foundry Local cung cấp API giống hệt OpenAI, nên cùng một đoạn code có thể trỏ sang Azure OpenAI chỉ bằng cách đổi URL và thêm API key.

7. Chuyển sang Web API

Core và Infrastructure dùng lại nguyên vẹn. Chỉ cần một project ASP.NET Core mới với Program.cs:

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddOemAiServices();          // y hệt dòng trong App.xaml.cs
var app = builder.Build();

app.MapPost("/api/assistant/ask",
    (AskRequest r, DeviceAssistant assistant, CancellationToken ct) =>
        assistant.AskAsync(r.Question, r.History, ct));

app.Run();

record AskRequest(string Question, List<ChatTurn>? History);
  • Chạy được vì WPF và ASP.NET Core dùng chung IServiceCollection của .NET Generic Host.
  • DeviceAssistant không lưu trạng thái — client gửi kèm lịch sử, nên server không cần session.
  • Lưu ý thật: trên server, IDeviceTelemetryService không thể đọc phần cứng của người dùng. Cần một implementation mới nhận telemetry do thiết bị gửi lên. Interface giữ nguyên — đó là lý do tách nó ra.

8. Điểm nhấn khi phỏng vấn

  1. Dependency Rule: Core không phụ thuộc ai. Đổi AI, đổi nguồn telemetry, đổi UI — không sửa nghiệp vụ.
  2. Use case nằm trong Core, không nằm trong ViewModel: logic ghép prompt test được trong 20ms, không cần UI hay model.
  3. MVVM với CommunityToolkit: [ObservableProperty], [RelayCommand(IncludeCancelCommand = true)] → tự có lệnh Huỷ, tự khoá nút khi đang chạy, loading bind thẳng vào AskCommand.IsRunning.
  4. Async đúng chuẩn: CancellationToken đi xuyên từ nút Huỷ tới request HTTP; PeriodicTimer cập nhật telemetry không chặn UI.
  5. DI kiểu ASP.NET Core trong WPF: Generic Host, constructor injection cả cho cửa sổ, không service locator.
  6. AI trên thiết bị (on-device): Foundry Local, chạy offline trên GPU/NPU — telemetry không rời máy. Đúng thứ OEM quan tâm.
  7. Prompt engineering thực tế: đặt telemetry ở system message thay vì trong câu hỏi, để model nhỏ trả lời đúng câu được hỏi ("1+1 = mấy" → "2") thay vì lúc nào cũng phân tích máy.
  8. Bộ nhớ hội thoại không trạng thái: giữ 8 tin nhắn gần nhất vì model nhỏ có cửa sổ ngữ cảnh ~4K token.
  9. Dám nói trade-off: telemetry trên cloud phải do thiết bị gửi lên; model nhỏ đôi khi trả lời sai.

9. Hạn chế hiện tại

  • Model nhỏ (Phi-4-mini) đôi khi sai ngữ pháp tiếng Việt hoặc khuyên sai. Có thể đổi sang qwen2.5-7b mà không sửa code — chỉ cần load model khác.
  • Bộ nhớ hội thoại mất khi tắt app.
  • NPU Intel của máy đang lỗi driver nên phải dùng bản GPU.
  • MockAIService chỉ là luật if/else, luôn trả lời về telemetry, không đọc câu hỏi.
  • Câu trả lời hiện ra một lần khi xong, chưa chạy chữ từng phần (streaming).
